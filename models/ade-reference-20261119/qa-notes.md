# 核验记录 · 2026-11-19

## 已验证

- Blender 4.5.3 本地实际导出可编辑 `.blend` 与 GLB；没有调用在线生成或原始 Meshy 下载。
- 最新结构统计和 SHA256 以 `model-check.json` 为准，校验脚本实际解析二进制缓冲区，检查三维位置、权重和动画变化。
- Khronos glTF Validator 2.0.0-dev.3.10 对最新 GLB 全量校验：0 错误、0 警告、0 提示；`maxIssues:0`，没有截断结果。
- 13 个带面部目标的图元，包含眼白、虹膜、瞳孔、两处高光、上眼线的闭眼控制，以及张嘴目标。实际闭眼渲染发现高光未闭合后，修复了 Blender 曲线转换影响其他选中物体而丢失形变的问题；增补结构断言先失败、修复后通过。
- 正面、三分之四、侧面、背面与招呼静帧实际查看，确认身体厚度、侧背面遮挡、服装和发束几何。
- 独立复核指出首版眼睛过大凸出、手臂外张和头饰被遮挡；修订后复核认为可辨认为参照阿德重建的角色，保留了主要身份特征。这不是用户已确认外观的记录。
- 浏览器实际载入最新 GLB，切换正/侧面、动作、暂停和张嘴检查。页面通过本机 4193 端口返回 200，模块与模型均由本地服务器提供。
- 桌面和窄屏布局检查；窄屏当次实际 DOM 宽度 416px，scrollWidth 416px，无横向溢出。不能将浏览器视口请求值 390px 当作实际观测值。
- 口型检查的独立 RAF 已改为暂停、页面隐藏或系统减少动态时不持续运行；来源审查确认停止/恢复条件。
- 修复旧版 Three.js PCFSoftShadowMap 设置后没有看到新增的该警告；开发日志保留早期历史记录，不能把旧记录当作本次加载新警告。

## 仍有边界

- 发型比录屏更尖、更有序；帽子折痕、表情和竹纹是参照重建，不能宣称一比一恢复原始 Meshy 网格。
- 手臂/手掌是按部件骨骼权重，当前动作幅度克制。没有做全帧穿模认证、布料模拟或任意舞蹈适配。
- 张嘴是音量/手动形变，不是音素同步；本轮没有改变原语音服务。
- 未在真实微信手机上测量帧率、内存或首次加载速度；台式机集成显卡上的预览成功不等同于所有手机通过。
- 模型制作阶段的成果尚未替换正式首页。首页接入、现有动作兼容与生产发布应独立核验。
