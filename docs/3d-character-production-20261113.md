## 制作流程

1. 通过已连接的 fal MCP 实时推荐并查验图生三维模型、定价、输出格式及可用绑定功能；不猜测端点或请求字段。
2. 用上述完整角色参考制作带纹理的 GLB。需要封闭或合理连接的身体、头发和服装体积，手臂与身体分离，避免宽袖粘连导致绑定失败。
3. 检查侧面、背面、头顶、脚底和衣袖；通过后再做人形骨骼绑定与蒙皮。生成三维网格不等于已经具备骨骼或面部表情。
4. 制作待机呼吸、思考、回头、转身及原地一圈。转身包含脚步和重心转移；转圈包含起步、加速、减速、落脚，保持脚底接触地面。头肩腰有轻微先后，避免整个模型像刚体转台一样运动。
5. 补充眨眼、微笑和口型需要的面部控制。语音继续使用现有 I/M09 音频和实际音量输入，保持既有方法接口及 iframe 来源校验。
6. 网页使用真实三维渲染、透视、灯光、接触阴影；检查手机性能、暂停恢复、减少动态和 WebGL 不可用时的静态回退。
7. 先实际观看模型与动作，再接入原站、部署并同步仓库。记录最终生成任务、模型来源、纹理和授权信息，不提交令牌或账户数据。

## 验收标准

- GLB 包含可渲染的三维网格与完整材质；连续旋转中能观察身体的真实厚度和遮挡。
- 不能采用朝向图片切换、贴图平面旋转，或用播放预录转圈视频冒充实时骨骼动作。
- 角色身份与参考一致；侧背面无重复面孔、穿孔、肢体融合、缺脚或大幅变形。
- 转身和转圈时脚、膝、胯、肩、头协同；不是对静态模型整体旋转后宣称自然动作完成。
- 张嘴和眨眼不会漂出脸部，语音停止后闭嘴；I 声线与主站其他功能保持。
- 自动检查只能验证文件结构、接口和加载，外观与动作质量必须实际观看。
